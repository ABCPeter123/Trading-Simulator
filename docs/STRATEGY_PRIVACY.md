# Private Strategy and Trading Data Policy

**Policy status: mandatory for every future Trading Simulator change.**

The public GitHub repository contains the **general trading engine, UI, research
algorithms, model implementations, documentation, and synthetic test fixtures**.
It must **never contain the owner's real strategy or the actual proprietary
output generated by optimization or research**.

The exact strategy being developed or deployed is confidential intellectual
property, even when the program that generated it is open source.

## What may be committed

- Generalized strategy compiler, runner, backtesting engine, stochastic and risk
  modeling algorithms, notifications, UI components, tests and documentation.
- Clearly fictional, synthetic strategy examples and test fixtures that are
  *not* derived from the owner's actual research or deployed strategy.
- Generic configuration templates with placeholders instead of credentials,
  proprietary parameters, private instrument baskets or live allocations.
- Public market-data API integration **source code**, not locally downloaded
  owner-specific outputs or trade and strategy archives.

## What must never be committed or uploaded to public artifacts

- Actual generated strategy rules/DSL code, signals, selected indicators,
  thresholds, parameter values, feature sets, target weights, regime logic,
  current deployed strategy, experimental candidates or best-performing versions.
- Actual backtests, optimization sweeps, scoring/ranking output,
  walk-forward results, model checkpoint weights and predictive signals.
- Owner-specific watchlists, intended trades, fills, orders, positions,
  brokerage statements, execution journals, live P&L, cash or leverage.
- Personal/private strategy names or identifiers that reveal the strategy.
- API keys, broker credentials, Discord webhooks, tokens, private keys,
  environment files with real values and notification destinations.
- Screenshots, test snapshots, logs, recorded responses, data dumps, PR bodies,
  GitHub issues or Actions artifacts containing real strategy logic or trades.

**Never even paste private output into GitHub issues, pull requests or commit
messages.** A CI log with redacted error content is safer than a log that prints
the secret to explain why it failed.

**Do not silently replace a private strategy with a 'generalized' version
that still exposes the owner's actual parameter choices or signal structure.**
Publish only synthetic, independently created examples.

## Where actual strategies live

The existing program already persists saved strategy versions to
`data/strategy_library.sqlite3`, and activated strategies in local
`data/arcade.sqlite3`. These directories are Git-ignored.

Use these private locations for any future persistent output:

- `data/` for local SQLite, Parquet and durable engine state.
- `.local-state/` for machine-only state and the isolated public demo.
- `private/`, `research/private/` or `models/private/` for manually
  exported proprietary strategies, optimization artifacts and checkpoints.
- Prefer encrypted backups **outside the Git checkout** for production/live
  trading strategies and financial records.

The default saved strategy library is local and does not commit its contents.
But being on your PC does not automatically make the data encrypted, backed
up or safe to expose via a web server. Future live deployments must add
authenticated access, access controls, backups and protected secret storage.

**Never send the owner's strategy to the public Cloudflare demo.** Public
demo users share its disposable sandbox and can see the demo strategies.
Keep all owner strategy analysis and actual portfolios on the private system.

## Enforced technical protections

1. `.gitignore` excludes runtime data, databases, files with common model
   weight/export extensions, private directories and credential files.
2. `scripts/check_private_artifacts.py` checks all Git-tracked paths and
   signatures of common credentials/serialized strategy exports.
3. The local Git pre-commit hook, installed by `start-local.ps1`,
   checks **the staged Git index**, including files force-added with
   `git add -f`.
4. GitHub Actions workflow `Block private strategy and trading-data leaks`
   independently runs the same check on pushes and pull requests.
5. The scanner never prints sensitive content on failure. Its tests
   check forced Git adds, source-code exceptions and secret signatures.

Run a manual check before every push:

```powershell
python scripts/check_private_artifacts.py --staged
git status --short
git diff --cached --stat
git diff --cached
```

The final `git diff --cached` is for the *owner's local review only*.
Do not paste it into a public issue or chat if it contains private data.
If your hooks are installed elsewhere and there is already a custom
pre-commit hook, the installer leaves it alone; manually chain the
privacy scan in your existing hook.

**Static checks are defense in depth, not a guarantee.** They cannot reliably
recognize every proprietary strategy embedded inside ordinary source
files, examples or prose. Contributors and agents must manually inspect
changes and avoid introducing real strategy parameters. CI runs after
content has already been pushed to GitHub, so the local pre-commit check
and review matter most. GitHub branch protection may be needed to
enforce a passing privacy status before merging.

## If information was accidentally pushed

Do not assume deleting it in the next commit makes it private.
Git history, forks, clones, cached archives, Actions logs and other public
copies may retain the information. Stop publishing, revoke/rotate affected
credentials immediately, treat disclosed strategy parameters as exposed,
and follow GitHub's sensitive-data history-removal procedures where
appropriate. Removal from Git history cannot revoke copies already taken.

## Continuing development

Future contributors should consult this policy and `AGENTS.md` before
adding strategy experiments, AI optimization, export features,
deployment scripts, notifications, trade journaling, telemetry,
screenshots or new public demos. Design private storage into the feature
before implementing its export or logging paths.
